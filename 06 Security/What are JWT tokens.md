  
what is json web tokens ??

JSON Web Token (JWT) is a compact, secure way to transmit information between two parties as a JSON object.

In Spring Security, JWT is commonly used for **stateless authentication**. Instead of storing user sessions on the server, the server gives the client a token after login, and the client sends that token with every request.

---

## Why JWT?

Imagine a normal session-based authentication:

1. User logs in.
    
2. Server creates a session.
    
3. Session ID is stored in a cookie.
    
4. Server keeps session data in memory/database.
    

With JWT:

1. User logs in.
    
2. Server creates a JWT token.
    
3. Client stores the token.
    
4. Client sends the token on every request.
    
5. Server validates the token.
    

No session storage is needed on the server.

---

## JWT Structure

A JWT has 3 parts:

```
xxxxx.yyyyy.zzzzz
```

```
Header.Payload.Signature
```

Example:

```
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJwcmF2aW4iLCJyb2xlIjoiVVNFUiJ9.abc123xyz
```

---

## 1. Header

Contains information about the token.

```
{  "alg": "HS256",  "typ": "JWT"}
```

Meaning:

- `alg` → Signing algorithm
    
- `typ` → Token type (JWT)
    

---

## 2. Payload

Contains user data (called **claims**).

```
{  "sub": "pravin",  "role": "USER",  "exp": 1750000000}
```

Common claims:

|Claim|Meaning|
|---|---|
|sub|User identifier|
|exp|Expiration time|
|iat|Issued at|
|role|User role|

⚠️ Payload is Base64 encoded, **not encrypted**. Anyone can decode it.

Never store passwords inside a JWT.

---

## 3. Signature

Created using:

```
HMACSHA256(    Base64UrlEncode(Header) +    "." +    Base64UrlEncode(Payload),    SecretKey)
```

This ensures:

- Token wasn't modified
    
- Token was generated by your server
    

---

## JWT Authentication Flow

### Login

```
Client  |  | username + password  vServer
```

Server verifies credentials.

If valid:

```
Server  |  | JWT Token  vClient
```

Example response:

```
{  "token": "eyJhbGciOiJIUzI1NiJ9..."}
```

---

### Subsequent Requests

Client sends:

```
GET /api/ordersAuthorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

Server:

1. Extracts token.
    
2. Validates signature.
    
3. Checks expiration.
    
4. Reads user information.
    
5. Allows request.

---

### JWT Filter

Runs on every request.

```
Authorization: Bearer <token>
```

Filter:

```
1. Read Authorization header2. Extract token3. Validate token4. Load user5. Set Authentication in SecurityContext
```

Then Spring Security knows who the user is.

---

## Why Use "Bearer"?

Header format:

```
Authorization: Bearer eyJhbGc...
```

"Bearer" means:

> Whoever possesses this token can access the resource.

So keep JWTs secure.

---

## Stateless Authentication

With JWT:

```
Request 1 -> TokenRequest 2 -> TokenRequest 3 -> Token
```

Server does not remember previous requests.

This matches:

```
.sessionManagement(    session -> session        .sessionCreationPolicy(            SessionCreationPolicy.STATELESS        ))
```

which you recently configured in Spring Security.

---

## Advantages

✅ Stateless

✅ Scales well

✅ No session storage

✅ Works great with REST APIs

✅ Can carry user roles and claims

---

## Disadvantages

❌ Cannot easily invalidate a token before expiration

❌ Token size is larger than a session ID

❌ If stolen, attacker can use it until it expires

---

## Real Example

User logs in:

```
{  "email": "pravin@gmail.com",  "password": "password123"}
```

Server returns:

```
{  "token": "eyJhbGciOiJIUzI1NiJ9..."}
```

Client stores it and sends:

```
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

For every protected API call.
